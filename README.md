# NFT Prompt Builder — публічний знімок коду

Streamlit-застосунок для створення mint-ready NFT-колекцій: від ідеї та trait-матриці
до промптів, зображень, метаданих ERC-721/Metaplex і експорт-бандла під конкретну
платформу мінту.

> **Це знімок коду для аналізу, а не робочий репозиторій.** Один коміт без історії,
> лише застосунок і тести: `app.py`, `api_server.py`, `services/`, `ui/`, `tests/`.
> Операційні матеріали (розгортання, моніторинг, бекапи, плани, CI) лишаються в
> приватному репо — вони не потрібні для читання коду. Тому тут **немає** секретів,
> адрес інфраструктури й ключів: периметр продукту тримається на секретах поза git,
> а не на приховуванні коду.

## Що всередині

**Двосервісна архітектура.** Streamlit UI (`app.py`, `:8501`) і FastAPI
(`api_server.py`, `:8000`) — SIWE-автентифікація (`/auth/*`), вебхук платежів,
публічні сторінки колекцій. Спільний стан — SQLite через `services/db.py`
(`DATABASE_URL` перемикає на Postgres без правки call-sites).

**Конвеєр із трьох незалежних етапів** із гнучкими точками входу:

1. **Текст** — конструктор промптів: Сингл / Специфічна група / Матриця ознак /
   Image-to-Prompt (зображення → структурована формула через vision-модель).
2. **Зображення** — паралельна черга (`services/pipeline_batch.py`) на gpt-image-1,
   Stability, Flux; ретраї, каскад на наступний двигун при збої провайдера,
   звірення списаних кредитів за двигуном, що **реально** згенерував.
3. **Куратор і експорт** — оцінки 1–5, відбір, метадані з provenance
   (`metadata_provenance.py`), IPFS-пін, бандл під цільову платформу.

**Структура промпту серії.** `services/prompt_service.py` збирає промпт як
`base object → style → variable traits → details → consistency fixers → tags`:
фіксована рамка серії випереджає змінні ознаки, бо вага токенів у диффузійних
моделей спадає зліва направо. Шаблон із трьома і більше trait-категоріями
збирається **пошарово** (по одному значенню з кожної категорії), інакше rarity
як збіг кількох ознак стає беззмістовною — див. `prompt_service.build_layered`
і `tests/test_prompt_structure.py`.

**Експорт під шість цілей** (`services/export_bundle.py`): OpenSea, Metaplex,
Thirdweb, generic, W3IR-пакет і **Candy Machine** — тека, готова під
`sugar deploy`, з config і guards; деплой гаманцем користувача, без приватних
ключів на сервері.

**Білінг і захист.** Кредити, вітальний баланс із Sybil-перевіркою, вебхук
платежів з at-most-once фулфілментом, денна стеля для безоплатних генерацій,
content-safety перед генерацією (блоклист + опційна модерація провайдера),
rate limit. Гроші й доступ покриті окремими тестами; на money-модулях стоїть
coverage-гейт із ratchet-підлогами.

**Класифікація гаманців** (`services/wallet_class.py`) — приклад того, що метрика
мусить знати, на яке питання відповідає. Дохід, маржа, ARPU й utilization
рахуються по **всьому** виторгу: оплата з власного гаманця через процесор
офіційна, і собівартість від особи платника не залежить. Але guard «чи хтось
**поза** проєктом цим користується» на сумарному числі відповіді не має — тож
зовнішній зріз існує окремо, і рішення про фічі беруть саме його. Командні
гаманці зашиті в код, а не в env: факт, уже зафіксований у репозиторії, не має
залежати від того, чи згадав про нього оператор у конфізі.

## Швидкий старт

```bash
pip install -r requirements.txt
cp .env.example .env          # заповніть ключі провайдерів
streamlit run app.py          # UI  :8501
uvicorn api_server:app --port 8000 --workers 1   # API :8000
```

`--workers 1` не косметика: nonce-стор SIWE-гейтвея тримається в памʼяті процесу,
тож на кількох воркерах підпис падає приблизно в половині випадків.

## Тести

```bash
python -m pytest -q     # 1576 passed, 5 skipped у цьому знімку
```

Ізольовані: без мережі, без реальної БД, без записів у робочі теки. У приватному
репо тестів більше — тут немає тих, що покривають операційні скрипти (бекапи,
моніторинг, деплой), бо самі скрипти не входять у знімок.

Стиль коду: коментарі й докстрінги — українською, чисті функції без Streamlit
(UI лише викликає), лінтер — `ruff` (`ruff.toml`).
